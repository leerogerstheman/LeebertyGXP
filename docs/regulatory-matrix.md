# 法规对照矩阵 · Regulatory Traceability Matrix

本文档把系统的每一项控制措施映射到具体法规条款，供验证文件（URS / IQ / OQ）与
检查时直接引用。**这是可审查的追溯证据，不是营销材料。**

系统内「合规态势」页面会实时核对其中 12 项，并给出**当前实际证据**
（如审计条目数、账号唯一性、第二要素绑定率），而非仅声明"已实现"。

## 三、数据完整性（ALCOA+）

| 原则 | 要求 | 系统实现 |
|---|---|---|
| **A**ttributable 可归属性 | 可追溯到具体操作人 | 唯一账号；每次操作记录 `actor_id`+`username`+`printed_name` |
| **L**egible 清晰可读 | 清晰、可读、永久保存 | UTF-8 存储；等宽字体；导出含 BOM |
| **C**ontemporaneous 同步性 | 操作当时记录 | 所有时间戳服务端生成，客户端无法指定 |
| **O**riginal 原始性 | 保留原始记录 | 审计追踪保留 `old_value`，修改不覆盖原值 |
| **A**ccurate 准确性 | 真实、无编造 | 计划外结果（失败签名、越权）同样记录；无删除功能 |
| **C**omplete 完整性 | 含全部元数据 | 元数据 + 标签页信息（`meta`）一并入链 |
| **C**onsistent 一致性 | 格式统一 | 规范化 JSON 序列化；封闭枚举 |
| **E**nduring 持久性 | 保存期内可读 | 单文件 SQLite，无外部依赖，格式长期可读 |
| **A**vailable 可用性 | 需要时可查阅 | 只读外部审计员角色 + 全量导出；`view` 事件留痕 |

## 七、明确不在范围内的事项

诚实界定范围，避免过度声明：

1. **不替代程序文件**。系统强制填写理由、保留审计追踪，但"SOP 该写什么"仍需站点自行编写。
2. **不替代人员培训**。系统管理培训记录与资质门槛，但培训内容与效果评估由站点负责。
3. **不替代验证活动**。系统提供证据与就绪度输入，IQ/OQ 签署仍须站点执行。
4. **不做法规符合性的最终判定**。就绪度评分与检查表是辅助排序工具；
   最终判定必须由具备资质的人员作出。
5. **不做电子签名的生物特征分量**。浏览器环境无法可靠实现。
6. **不做数据库文件级加密**。SQLite 加密需第三方扩展，与零依赖设计冲突；
   依赖操作系统文件权限与磁盘加密。
7. **不做多站点数据同步**。设计为单实例本地部署，满足车间/实验室级使用。
